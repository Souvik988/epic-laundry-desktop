# Epic Laundry UX Audit — 2026-09-03

Status: `PARTIAL` — targeted review and remediation complete; full release audit remains open.

## Scope

Persona: store owner / counter operator, time-poor, moderately technical, using the
desktop during a live shift.

Evidence reviewed:

- the supplied 55.872-second, 1920×1080 screen recording;
- the installed Windows Electron build;
- the authenticated demo workspace;
- the Operations and Finance & Compliance navigation flows;
- a rebuilt browser runtime at approximately 1050px wide;
- accessibility audit and console error output.

## Findings and disposition

### High — core menu opened a different legacy product

Operations opened static pages such as Manufacturing and Projects & Services.
Finance & Compliance opened static Accounting, GST, Banking and Returns pages.
Those pages showed the old “Epic BOS” title, blue theme, and generic ERP forms.
They did not share the Laundry Desk order, garment, payment, invoice, or store
authority. This made a core navigation action look like a broken hand-off.

Disposition: fixed. The desktop menu now routes only to authenticated Laundry
Desk routes. New Operations and Finance & Compliance hubs connect the existing
laundry workstreams. Unknown React routes redirect to the Laundry Dashboard.

### Medium — typography was not a controlled product asset

The application depended on OS fonts and mixed Aptos, Palatino, and fallback
stacks. This made the visual system change across machines and gave headings a
demo/template feel.

Disposition: fixed for the active desk. Manrope is bundled offline and used for
body, display, and heading tokens. Noto Sans Devanagari is bundled as the Hindi
script fallback. The runtime reports the bundled stack and no longer uses the
old decorative serif heading family.

### Medium — generic ERP fallback could reintroduce the mismatch

The React router previously rendered a generic ERP shell for unknown paths.

Disposition: fixed. Unknown application routes return to the Laundry Dashboard.
The legacy static assets remain preserved for compatibility and auditability but
are not exposed from the product navigation.

### Open — legacy backend domain is not automatically a connected module

Generic ERP metadata and APIs still exist in the repository. They are not
claimed as integrated merely because they exist. Reintroducing accounting,
inventory, HR, projects, or banking requires an authority matrix, migrations,
shared order/store identity, and cross-channel tests.

Disposition: `EPIC_EXTENSION` / `NEEDS_VERIFICATION`. Keep preserved, hidden,
and out of the operator workflow until those contracts exist.
