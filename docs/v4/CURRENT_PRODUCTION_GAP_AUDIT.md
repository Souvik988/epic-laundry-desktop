| Area | Classification | Evidence / decision |
| --- | --- | --- |
| Local Electron, Fastify and SQLite/WAL | VERIFIED_CURRENT | Existing desktop starts a loopback-only authenticated local server and passes restart/workspace tests. Preserve it. |

| Legacy event outbox | PARTIAL | It marks events published before a remote acknowledgement. It remains an internal legacy relay and is not suitable for marketplace delivery. |
| Marketplace edge sync | PARTIAL / EPIC_EXTENSION | Durable acknowledged outbox/inbox, device registration, checkpoints, retry/dead-letter states, local simulator, ordered projection and cross-channel self-tests now exist. A real signed cloud transport and remote contract are still unavailable. |
| Adjacent platform backend | VERIFIED_REFERENCE | `../Lndry_backend` has customer orders, payment and rider APIs, but its documented model is not a desktop edge-sync contract. Do not call it from desktop until both sides agree a versioned contract. |
| Fixed-scale financial normalization | VERIFIED_CURRENT | Existing money/reconciliation/normalization tests pass. Preserve and extend rather than replace. |
| Tax / invoice compliance | PARTIAL / NEEDS_LEGAL_VALIDATION | Fixed-scale line-level tax, effective-dated policy, supplier profile/readiness, immutable canonical invoice/credit-note snapshots and no-fake-QR print routes exist. Registered supplier readiness now also fails without an effective approved classification; unregistered profiles remain explicitly operational. Configured-store laundry bookings and full cancellation/supersession reversals now create/link canonical evidence with a submitted credit note and no double reversal. Production entry-point invoice/posting paths now fail closed without a persisted supplier profile instead of accepting an injected demo state. TDS rules and GST ECO TCS controls are live; income-tax TCS is now tenant-scoped and approved-policy-gated. Finance command-center visuals now include tax trend, quality/return signals, settlement movement, and service-volume/quality load. Remaining ERP document paths, provider evidence and legal approval for production GST/e-invoice and marketplace withholding claims remain incomplete. Marketplace materialization now fails explicitly when the supplier profile is incomplete. |

Customer identity increment: Customer 360 now exposes a deliberate `marketplace_customer_links` projection (migration 36). Owner-only linking is strict, branch-scoped, idempotent, collision-protected and revocable; linked marketplace orders appear only through an active explicit link. Automatic name/phone merging remains prohibited. The real cloud account-link contract and platform customer projection are still external dependencies.
| Catalogue imagery | BUG → partially fixed | Booking previously inferred visuals from free-text names and defaulted unknown garments to a shirt. V4 now uses explicit visual keys, corrected thirteen wrong active mappings, generated a complete contact sheet, and ships every active runtime image as a 256px WebP derivative (zero asset-budget warnings). Six closely related generic/shared mappings still require visual-owner review. |
| Online Orders operator surface | EPIC_EXTENSION / PARTIAL | Runtime-inspected queue cockpit now exposes source, request, payment, sync, acceptance/rejection, physical intake entry, materialization controls, local pickup scheduling/collection, and a privacy-safe customer-facing status/timeline projection derived from recorded request, intake, reassessment, marketplace, pickup, and local-order events. Status mappings are store-configurable and reassessment approval overrides the operational status until decided. Queue visibility is available to `orders.read`; mutations remain `orders.edit`-protected with a clear read-only state. Main store-order search now uses bounded SQL-backed pages with deterministic ordering, an optional keyset cursor, and a maintained FTS5 projection. Global search now uses bounded SQL/FTS result sets for customers, orders/invoices, garment tags, and containers. A 100k-customer/500k-order fixture measured 501 ms customer-name search; equivalent deep offset paging measured 823 ms versus 330 ms with the cursor. Richer completed-order work-card integration and live cloud route assignment remain. |
| Customer privacy boundary | EPIC_EXTENSION / PARTIAL / NEEDS_LEGAL_VALIDATION | Local vendor-scoped export, correction-request, erasure-request, legal-hold/active-order rejection, PII scrubbing with accounting-reference preservation, consent scrubbing, address archiving, audit evidence, and authenticated API coverage now exist. Export responses are checksum-labelled and explicitly scoped to the local vendor/store projection. DPDP purpose, retention, notice, grievance, breach and legally required exception policy still require current legal/CA validation and control-plane alignment. |
| Legacy customer portal access | BUG → fixed locally | The old public route authorized access by customer ID and read from the process-default tenant. It now requires a short-lived HMAC token issued by an authenticated customer-reader, binds the token to tenant/store/customer, rejects missing/tampered/expired/mismatched tokens, and preserves read-only behavior. This local route is not a substitute for the marketplace cloud customer contract. |
| Production signing / updates | EXTERNAL_BLOCKER | Internal Windows builds remain unsigned, but the release manifest now labels them `internal-unsigned` and a production build hard-fails unless the approved version, Authenticode credentials, trusted HTTPS update feed, and Ed25519 manifest keys are present. No production certificate/feed evidence is present. |

The product is **not production-certified**. This document is an evidence record, not a release approval.
