# Security and privacy review

Existing strengths: loopback-only desktop server, authenticated startup handshake, sessions/RBAC, store scope, encrypted backup test coverage, redacted diagnostics, event-ID/payload-collision rejection, ordered aggregate checks, and fail-closed provider webhook verification.

V4 threats requiring implementation/testing: stolen device credential, forged payment/GSP webhook, vendor/store IDOR, aggregate-version tampering, stale quote, unsafe media, SSRF, catch-up-safe rate limiting, and PII exposure in exports/backups. Local event replay and payload collision controls are verified against the simulator; cloud-issued device credentials, signed transport, and cross-tenant authorization remain external-contract work.

The local privacy boundary now provides authenticated vendor-scoped export, correction requests, erasure requests, active-order and legal-hold rejection, PII scrubbing with accounting/operational references retained, address archiving, consent scrubbing, checksum-labelled exports, and audit events without writing customer PII into the audit payload. API and domain self-tests cover export, correction, erasure, request idempotency, store isolation, and unauthenticated access denial. This is an operational control, not a legal certification: DPDP purpose/notice, retention, grievance, breach, controller/processor allocation, and marketplace deletion propagation remain **NEEDS_LEGAL_VALIDATION** and require the real control-plane contract.
