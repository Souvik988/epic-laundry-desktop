# UX / QA Audit: Epic Laundry vs UniClean

**Date**: 2026-08-28
**Scenario**: Start the counter day, review performance, book a garment order,
move work through fulfilment, collect payment, and inspect reports/settings.
**Persona**: Busy counter operator who needs fast, obvious actions and a clear
recovery path when interrupted.
**Surfaces**: Installed Epic Laundry desktop app (local Chromium webview) and
the signed-in UniClean reference at `app.myuniclean.com`.
**Viewport**: Desktop baseline (1280px); DOM and console checks performed.

## Executive summary

Epic Laundry now has a coherent local laundry workflow with a significantly
stronger Overview than the reference: global Today / Last 7 days / Lifetime
filters, six KPIs, revenue and collection trend, lifecycle and customer donuts,
acquisition, receipts, service demand and throughput. The main reproduced
blocker was not the booking API: the installed app was sitting at first-run
owner authentication, so every operational page was hidden. A local owner
session was restored and booking was verified to become enabled once a customer
and garment are selected.

UniClean remains broader in catalogue breadth and has more granular settings
sections. Epic's local catalogue now contains a 13-item branded starter master
and supports owner-managed expansion; it should not claim full reference
catalogue parity until the remaining master-data import is completed.

## Reproduced findings

### Critical — Fresh installation blocks all work until owner setup

- **Where**: `AuthGate`, first launch.
- **Observed**: The refreshed install opened at “Create the owner account” even
  though seeded demo orders existed. This made “Book order” and every other
  operational route unreachable.
- **Action taken**: Restored the existing local `souvik` owner session with a
  local demo password; no UniClean account or API was changed. The password is
  intentionally not stored in the repository report.
- **Recommendation**: Keep the secure owner gate, but add a first-run handoff
  card that states exactly how to finish setup and where to find the local
  credential. Do not silently bypass authentication in production.

### High — Catalogue breadth is smaller than the reference

- **Where**: Order booking and Garments & prices.
- **Observed**: UniClean's Order & Billing surface exposes a much larger
  garment master list and more category/service combinations. Epic now ships
  thirteen branded garment visuals and a 13-item starter master (including
  blazer, dress, jeans, hoodie, and kurta coverage), while the underlying
  master-data import remains
  the governed path for additional customer-specific rows.
- **Recommendation**: Complete the governed import path for the remaining
  master data rather than hard-coding remote reference content. Preserve local
  rate snapshots on booked orders.

### Medium — Reference has per-card statistics ranges

- **Where**: UniClean `/statistics`.
- **Observed**: UniClean exposes separate Today/Week selectors on its four
  statistic cards. Epic uses one global range control, but adds richer combined
  charts and Lifetime coverage.
- **Recommendation**: Consider optional per-panel drill-down only if operators
  request it; the global range is faster and keeps the overview coherent.

### Low — Functional icons and product art use different visual systems

- **Where**: Sidebar/actions vs booking/catalogue cards.
- **Observed**: UniClean uses icon-led controls and product photos; Epic uses
  code-native Lucide icons and approved local branded raster visuals.
- **Recommendation**: Keep Lucide for functional controls (better keyboard and
  accessibility behavior) and continue using branded art only for garments,
  empty states and identity surfaces.

## Workflow comprehension

### Threads tested

- **Start the day → Overview → queue**: complete. Dashboard and Overview both
  surface operational counts; Overview is now immediately after Dashboard.
- **Customer call → book order → tag**: complete to ready state. Customer can be
  searched or created, garment/service lines can be added, totals are quoted by
  the server, and the booking action enables only when prerequisites are met.
- **Book → assign rider → fulfil → collect**: wired across Store orders,
  Pickup & delivery and the order detail ledger; backend and E2E tests pass.
- **Master data → counter**: complete for the shipped catalogue; broader
  reference catalogue import remains the primary parity gap.

### Wayfinding

The current sidebar highlights the active route and uses task-oriented labels.
The strongest continuity improvement is the Overview placement immediately after
Dashboard. Order details keep payment, fulfilment, tags and timeline together.

### Visual cues

Primary actions are visually dominant, status pills are color coded, empty states
explain the next action, and the Overview is now populated by deterministic demo
data on a fresh install.
